# Security route matrix (API)

Every REST route and every client → server Socket.IO event, with who may call it, what it checks,
its rate limit and the tests that prove it. Part of the Step 20 security review (OWASP ASVS L2 +
API Security Top 10); findings are in `docs/security-findings-backend.md`.

**This file is checked by a test.** `backend/src/security-tests/route-matrix.test.ts` fails when a
route is added, removed or renamed without updating this table, or when a socket event is missing.
Review a new route (auth, authorization, validation, rate limit, tests) and add its row here.

## What every route gets (tested for all of them by `route-matrix`)

- **Authentication:** every route except the `public` ones answers `401` without a session
  (`UNAUTHENTICATED`, or `SESSION_EXPIRED` when a dead cookie was sent). Checked in `onRequest`,
  before the body is parsed or validated. `admin` routes answer `403` to a non-admin.
- **CSRF / origin check** (`backend/src/plugins/origin-check.ts`): a `POST`/`PUT`/`PATCH`/`DELETE`
  is refused with `403 FORBIDDEN` when its `Origin` is not `APP_URL` or one of `CORS_ORIGINS`
  (`Origin: null` included), or, with no `Origin`, when `Sec-Fetch-Site` is `cross-site` or
  `same-site`. A request with neither header is not from a browser (curl, probes, server to server):
  it carries no ambient cookie a site could abuse, so it is allowed and still needs a session.
  Reads (`GET`/`HEAD`) are not blocked: CORS keeps other sites from reading the answer. The socket
  handshake checks `Origin` the same way and authenticates with the session cookie.
- **Validation:** params, query and body are Zod schemas from `@zuvo/protocol`; malformed ids answer
  `400`/`404` (sweep). Errors use the shared `ApiError` shape; `5xx` never carry internals.
- **Not yours = not found:** someone else's chat, message, file, folder, session, device, wallpaper
  or scheduled message answers `404`, exactly like a missing one. `403` is used only where the
  caller may already know the thing exists (a member who is not the sender, not an admin).
- **Rate limits:** a global per-IP limit of 300 requests/minute (Redis-backed in production, loopback
  exempt for container probes), tightened per route below. Sending messages over the socket is
  limited to 20 per 5 s per user.

Test names below are files in `backend/src` without `.test.ts`: `route-matrix`, `idor-*`,
`auth-hardening` and `production-surface` are in `backend/src/security-tests/`.

## Socket.IO events (client → server)

Every event: payload validated against its `@zuvo/protocol` schema, session re-checked (revoked or
expired → `SESSION_EXPIRED` and the socket closes), always acknowledged with `ok`/`error`.

| Event                | Authorization rule                                                                                      | Limit               | Tests                                           |
| -------------------- | ------------------------------------------------------------------------------------------------------- | ------------------- | ----------------------------------------------- |
| `message:send`       | member of the chat with send rights (404/403); reply quotes and files only from chats/uploads I can see | 20 per 5 s per user | idor-chats, idor-messages, idor-media, realtime |
| `read:update`        | member of the chat (404)                                                                                | —                   | idor-chats, realtime-receipts                   |
| `delivered:update`   | member of the chat (404)                                                                                | —                   | idor-chats, realtime-receipts                   |
| `voice:played`       | member who can see that voice note (404)                                                                | —                   | idor-chats, voice                               |
| `typing:start`       | member of the chat; nothing is broadcast otherwise                                                      | —                   | idor-chats, realtime-typing                     |
| `typing:stop`        | member of the chat; nothing is broadcast otherwise                                                      | —                   | realtime-typing                                 |
| `presence:subscribe` | any signed-in user; last-seen privacy applied                                                           | 20 per 10 s         | realtime-presence                               |
| `presence:active`    | own presence only                                                                                       | —                   | realtime-presence                               |
| `window:state`       | own push attendance only                                                                                | —                   | push-delivery                                   |
